# 组队版的消息渠道

项目经理在网页建项目、邀请成员，成员在自己选用的聊天软件接任务，也可以在 Claude Code 继续工作。网页工作台、常在线服务和以下协作策略是待验证的产品原型。当前发布物提供可运行的渠道路由接口和本地测试。

## 适配器边界

服务由配置选择启用哪些驱动。`createRouter({drivers, enabled, bindings})` 支持按名称注册同一接口的不同实现。每条绑定关联公司在该平台的租户、外部用户和会话、内部项目及成员。员工可在不同入口处理同一个项目编号和任务编号。

| 调用 | 驱动与服务各自处理什么 |
| --- | --- |
| `router.notify(channel, event)` | 服务先判断谁应当收到通知。路由检查绑定，只把事件编号、项目编号、任务编号、事件种类交给驱动。驱动决定渲染样式和投递方式。 |
| `router.receive(channel, rawRequest)` | 驱动先按平台规则验证签名、时效和来源，再提取回调身份；路由从可信绑定取内部成员身份，生成待处理的动作。 |
| 决策与执行 | 协作服务按当前权限、任务版本及回调去重键判断是否执行。驱动收到点击本身不产生批准、执行或关单。 |

执行 `node --test test/channels.test.mjs` 可验证启停、发送、回调和跨项目隔离。示例驱动是内存测试替身。飞书、企业微信、Slack 等平台需要各自的生产驱动、凭据和收件人绑定；WorkBuddy 的具体接入方式需要验证其可用接口。密钥由部署环境管理。

## 已确认的原型行为

- 经理要方案就停在方案，要交付就可自动拆解、派工。项目记录区分对结果负责的人与当前执行步骤的助手。
- 成员离线时，常在线项目助手可以用共享资料推进；需要私人资料或本人授权的步骤留给负责人。已授权范围内的操作可继续。
- 私人原话、私人录音默认留在个人侧。与任务直接相关的必要事实可以送到需要的人。会议上已决定的事项进入所属项目共同记录，有指定可见范围时服从该范围。
- 可核验的验收条件允许凭证据关单；需要取舍的工作停在待决策。以成员身份对外行动要有该成员授权。
- 项目主脑只获知其他项目对成员可用时间的影响。跨项目冲突由公司级主脑建议，有权限的人决定。
- 日常待办与待决策摘要送到成员选择的消息渠道。网页承担跨项目总览、邀请和排期。服务端保存任务与版本，个人 Agent 上线后拉取未读变化；从不同渠道提交的同一操作应在服务端去重。

可先用本地路由验证协议，再选择第一款真实平台试通一个项目、一条任务、一次回执。
