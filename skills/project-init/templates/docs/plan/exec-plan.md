# 执行计划

> 多阶段项目才需要这份文件。它回答「按什么顺序做、谁做、做到什么算一个阶段走完」。
> 任务的细节在 `docs/specs/`，状态在 [BOARD](../BOARD.md)，这里只写顺序和依赖。计划变了就改这份文件，被推翻的决定记进 `docs/adr/`。

## 分工

| 角色 | 谁 / 哪个模型 | 做什么 |
| --- | --- | --- |
| 产品负责人 | 你 | 定方向、拍板、验收 |
| 总控 / 架构 | 主会话（最强的模型） | 写说明书、评审、合并、改共享文件 |
| 执行者 | 任务会话（主力编码模型） | 按说明书实现 |
| 调研 | 子代理（便宜的模型） | 查官方文档，写 `docs/research/` |

执行者的固定流程：读 AGENTS.md → 读说明书 → 先写失败的测试 → 实现 → 跑「完成的定义」→ 派审查 → 填说明书的「结果」→ 交接。
