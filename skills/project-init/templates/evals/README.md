# evals · 回归用例

这里存的是**真实使用中出过的错**，每个错一条。它们是这个项目自己的评测集：改提示词、换模型、调参数之前和之后都跑一遍，才知道是变好了还是变坏了。

## 规则

1. **只收真实出过的错。** 不凭空编用例。用的时候发现输出不对，就记一条（`/agent-project-kit:flow case`）。
2. **先记用例，再修。** 顺序反了，就没法证明修好了。
3. **去掉敏感内容。** 真实姓名、联系方式、密钥、未公开的业务内容，换成占位内容再存。原始数据不进仓库。
4. **写清楚怎么判定。** 能用程序判定的（包含某个字段、不包含某句话、数字在某个范围内）优先；只能靠人看或者靠另一个模型打分的，写明判定的问题和通过的标准。
5. **修好之后不删。** 状态改成「已修复」，注明由哪个测试或哪次评测守着。

代码本身的 bug 不放这里，直接写成一个失败的单元测试。这里只放「代码没错，但模型的输出不对」的情况。

## 怎么跑

（项目有了评测脚本之后，在这里写命令，并把它加进 AGENTS.md 的「命令」。在那之前，改提示词或换模型时，照着每条用例的输入手动跑一遍，把结果记在用例的「复查记录」里。）

## 每次模型调用要留的记录

评测要能重现，前提是每次调用都留了痕。至少记这些：

| 字段 | 说明 |
| --- | --- |
| 时间 | 调用开始的时间 |
| 模型 | 完整的模型名和版本 |
| 提示词版本 | 提示词文件的版本号或内容哈希 |
| 输入 / 输出 token | 用来算钱和查异常 |
| 费用 | 按当时的单价算 |
| 耗时 | 毫秒 |
| 结果 | 成功 / 失败，失败的原因 |
| 关联 | 属于哪个任务、哪条数据 |

记录里不放密钥，也不放不该外传的原文。
